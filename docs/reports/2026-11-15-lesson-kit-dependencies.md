# Lesson-kit dependency review

The two direct development dependencies introduced by PR469 were checked on 2026-11-15 against npm metadata, their upstream repositories and the installed lockfile's npm audit. Both are pinned to the current stable versions reported by npm:

- `puppeteer-core` 25.17.0: [Puppeteer](https://github.com/puppeteer/puppeteer), Apache-2.0, established actively maintained browser automation. The core package uses the operator's explicitly selected Chrome rather than downloading a browser. Playwright is a viable alternative but would duplicate this submitted builder's browser integration; a bare Chrome CLI cannot implement its in-page pagination checks as directly.
- `qrcode` 1.5.4: [node-qrcode](https://github.com/soldair/node-qrcode), MIT, established QR generator with a slower release cadence. The stable version remains 1.5.4. Its SVG output is generated from the lesson URL locally. Writing our own QR encoder would add protocol and test burden without improving this bounded use. No installed advisory names either package or its newly introduced dependency chain.

These packages serve the local PDF builder; ordinary production builds do not launch Chrome. The fact-cleared committed PDFs are preserved byte for byte.

The patched Astro no longer brings `esbuild` transitively, although eleven existing component/cache test harnesses import it. Declare `esbuild` 0.28.2 explicitly as a development dependency (the same version already in the original lockfile, and npm's current stable). [Upstream](https://github.com/evanw/esbuild) is actively maintained, widely used and MIT-licensed; its [advisories](https://github.com/evanw/esbuild/security/advisories) concern older releases/development servers or the Deno wrapper, not this Node build API use. The final npm audit checks the installed version. Replacing all harnesses with Rolldown would add unrelated test migration risk; relying on a transitive import again would leave the dependency undeclared.

The initial audit reports existing Astro and XML parser advisories: [dynamic tag attributes](https://github.com/advisories/GHSA-mh32-jxcr-mh9f), [Node image endpoint paths](https://github.com/advisories/GHSA-r3h5-4585-7x3w), and [XML stop-node parsing](https://github.com/advisories/GHSA-474x-hrwr-fgx4). This is a static Cloudflare site without the Node image endpoint; no exploit is inferred from the advisory count. Compatible patched lock resolutions will nevertheless be validated before deployment. Final versions and audit results are recorded in the delivery report.
