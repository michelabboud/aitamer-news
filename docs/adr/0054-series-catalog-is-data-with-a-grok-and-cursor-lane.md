# 0054: The series catalog is data, with a series lane for the Grok and Cursor Apps

## Status
Accepted 2026-11-11 by Michel ("i want grok and cursor to be able to update that file"; the JSON design approved the same day, with "the json is used only in compile not sent to site"). Adds a lane beside 0018, 0030, 0036 and 0050; changes nothing for them.

## Context
The newsroom bots run multi-part series (Kubernetes from Zero is the first with 33 parts) and need to add and edit series rows themselves. The rows lived in `src/data/series.ts`, which is TypeScript: the site build, `npm run check:posts` and the tests all execute it. The Grok App merges its own pull requests once the required checks pass (#446 and #449 were authored and merged by it). A lane that admitted `series.ts` would therefore let a confused or prompt-injected bot merge code that runs inside the deploy build and ships to every reader. Every existing bot lane changes data only (posts, author files, `pins.json`), never code.

The Grok App writes `grok/*` branches, and every `grok/*` pull request is routed to the article admission workflow, which takes the observation check names and never runs this repository's path guard. The Cursor App had no lane at all: every Cursor pull request fails `publisher-paths`.

## Decision
1. **The rows move to `src/data/series.json`.** `src/data/series.ts` stays as the code that reads it and exports `SERIES` and `seriesMeta` unchanged, so every caller keeps its import. The file is imported at build time and rendered into HTML; it is never copied into `dist/` and no client script contains it.
2. **A strict reader, `src/lib/series-catalog.ts`.** The file is bot-writable, so `parseSeriesCatalog` trusts nothing: an array of objects; only `slug`, `title`, `description`, `heroImage`, `heroAlt`; a lowercase slug of at most the site's slug length, used once; title (80), description (240) and alt (200) trimmed plain text with no control characters, no invisible formatting characters (zero-width, direction marks and overrides) and no `<` or `>`; a hero only as `https://bots.aitamer.news/heroes/series-<its own slug>-<8 hex>.jpg`, always with its alt. Any problem throws and fails the build, the tests and `check:posts`, naming the row. `npm run check:media` still checks a configured hero and its WebP twin are on the media host.
3. **A series lane in `scripts/check-publisher-paths.mjs`.** It applies only when the pull request's author and this event's sender are both the Grok App (`GROK_ACTOR_ID`) on `series/<suffix>`, or both the Cursor App (new repository variable `CURSOR_ACTOR_ID`, account 206951365) on `series/<suffix>` or `cursor/series-<suffix>`; on `opened` or `synchronize`; in this repository. The suffix rule is the pins lane's. It admits exactly one changed path, `src/data/series.json`, **modified only** (the file exists, so adding, deleting, renaming or copying it is refused), a plain file. The pins and series lanes share one implementation of that single-file rule. No login fallback; unsetting `CURSOR_ACTOR_ID` closes the lane to Cursor, unsetting `GROK_ACTOR_ID` closes it (and Grok's article lane) to Grok.
4. **Grok's lane branch is `series/`, not `grok/`.** `grok/` is woven into three workflows, the admission script and image approval as an observation prefix; carving an exception out of all of them would touch the trust-critical admission path. `series/` and `cursor/` are not observation prefixes, so their pull requests get the required `publisher-paths` name and this script's verdict (a test pins that).
5. **Rulesets, defence in depth.** A live ruleset lets only the Grok App, the Cursor App and admins create, update or delete `series/*` branches, and `series/*` joins the bot-branch exclusions of the two maintainer-branch rulesets. The numeric identity in the check is the rule.
6. **More than one merge base fails closed.** The path guard used to judge a pull request against a single merge base; a crafted criss-cross head could show only lane files there while reverting another parent's work in what `main` receives. `collectPullRequest` now refuses when `git merge-base --all` returns more than one commit. This tightens every lane, not only this one.
7. **A series without its own icon shows a neutral default** (`src/assets/series-icons/default.svg`), so a bot can add a series without touching code; a person may draw its own icon later. A hero stays optional.

## Alternatives rejected
- **Admit `src/data/series.ts` to a lane as it is.** Lets a self-merging bot change build-time code. Refused for that reason alone.
- **Keep the catalog as code and let only the maintainer change it.** The bots open the row, the maintainer merges by override. It works for one series, but makes every row edit a manual merge and is what Michel asked to remove.
- **`grok/series-*` for Grok.** Needs an exception in every `grok/` observation expression and in admission; a mistake there could hand an observation route to a non-article pull request. A separate prefix touches none of it.
- **A whole `src/data/` lane.** `pins.json`, `topics.json` and `prepared-heroes.json` belong to other owners.
- **Allow adding the file.** It already exists on main; nothing legitimate adds it, and refusing `A` refuses a delete-then-add trick for free.

## Consequences
A holder of the Grok or Cursor App's key can change the series catalog, and nothing else through this lane, by a pull request that still needs every required check; the build refuses any malformed or hostile row. Grok can merge such a pull request itself; Cursor cannot update `main` and needs the maintainer to merge. A removed row that posts still name fails the build (`seriesProblems`), so a bot cannot orphan a series by deleting it. Anyone who can change repository variables could point `CURSOR_ACTOR_ID` at another account and give it the series lane (only the series catalog), the same exposure the other lane variables carry. Cursor's other pull requests (diagrams, posts) still have no lane and merge only by the maintainer's override after review.
