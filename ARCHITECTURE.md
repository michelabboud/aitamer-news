# Architecture

aitamer.news is a static news site. Astro renders every page to HTML at build time; there is no server-rendered page and no database.

## Build

- **Framework:** Astro 7, `output: 'static'`, MDX and sitemap integrations (`astro.config.mjs`).
- **Content:** Astro content collections defined in `src/content.config.ts`.
  - `src/content/comments/*.json` — approved reader comments, one file per post, written by the desk's publisher and validated against the strict comment contract (`src/content/comment-schema.ts`, ADR 0006; loader `commentsLoader` in `src/content/data-file-loader.ts`, which names entries after their files and is silent when the directory has no file yet). `scripts/check-comments.mjs` (in `npm run check:posts`) fails a file with no post. The post page bakes them in at build time: `src/components/Comments.astro` renders each as `<article id="c-<id>">`, with text through `renderCommentHtml` in `src/lib/comment-text.ts` (escaped plain text, paragraphs, `http(s)` links only with `rel="nofollow ugc noopener noreferrer"` and `dir="ltr"`; every character in the schema's `FORBIDDEN_CHARACTERS` list stripped except the newline and the two joiners — the same list the schema refuses, not a copy — and never the Markdown pipeline). A link's visible text is built from the parsed URL, never from what was typed: `scheme://host` whole, the host in its punycode form, then the path decoded for reading and cut after the host at 80 grapheme clusters; a URL with a user name or password, or with an IP-address host in any form, is left as text. Name and text carry `dir="auto"`, and `.comment` has `contain: paint`, so a flood of combining marks cannot paint over its neighbours. The Campfire's newest-comment rows do the same: `contain: paint` on the row, `dir="auto"` and `unicode-bidi: isolate` on the name and the excerpt. The `NewsArticle` JSON-LD carries `commentCount` and the 50 newest as `Comment`s, each with its own `url` (the canonical URL plus `#c-<id>`); `CommentCount.astro` is a build-time count its caller passes in — the home page and the Campfire look the threads up once per page (`commentCountFor`), never once per row. `getCommentThreads()` in `src/lib/site.ts` reads the collection once per `getStaticPaths`, and each post's `cacheKey` carries its own thread's stamp, so a new comment re-renders only that post. It checks the directory for a comment file first (`hasDataFiles`, `src/content/data-files.ts`: a regular file, by `lstat`, named `<slug>.json` in lowercase — exactly what `check-comments.mjs` accepts) rather than globbing: a glob would put every comment file into every post page's module graph, which the incremental build hashes. The publisher lands its files by pull request only, held by the required check `publisher-paths` (`.github/workflows/check-publisher-pr.yml`, logic in the dependency-free `scripts/check-publisher-paths.mjs`): on `pull_request_target`, from `main`'s own copy of the workflow, installing nothing and never checking out the pull request; the verdict is pinned to the event's head commit, with changes from `git diff --name-status -M` against the merge base and modes from `git ls-tree`, on fetched objects. Every pull request is held to the rule unless its author and the event's sender are both the maintainer by numeric id (`vars.MAINTAINER_ID`) on an `opened` or `synchronize` event; it fails if any path is not `src/content/comments/<slug>.json` or `src/content/reactions/<slug>.json` (the publisher's two lanes, ADR 0008), a rename leaves its lane, or an added file is a symlink, submodule or executable. Deletions inside a lane pass. The ruleset requires `publisher-paths` and the `Check posts` job `check`, both from GitHub Actions. As a second line, the deploy refuses a push by the publisher (`github.actor_id` equal to `vars.PUBLISHER_ACTOR_ID`, a numeric id) that changes anything else, judged by the script as it was before the push; it judges that one push only, so a refused commit is reverted before anything else lands. Removal of a published comment is the desk's delete command, never a hand edit alone: the publisher regenerates each file from the desk's database. Details: `CONTRIBUTING.md`, ADR 0007.
  - `src/content/reactions/*.json` — readers' reaction totals, one file per post with a total above zero, written by the desk's publisher (not yet live: `REACTIONS_LIVE` in `src/lib/site.ts` is false, so no page shows them). Contract v1 is `src/content/reaction-schema.ts` (strict; `{ version, slug, reactions: [{ id, n }] }`, ids sorted and unique, `n` a whole number ≥ 1, no timestamp so equal totals give equal bytes), published at `/contract/reactions.schema.json` and `/contract/v1/` and frozen by `src/content/reaction-schema.v1.snapshot.json`. An id is checked for shape, not membership: the set is `REACTIONS` in `src/lib/reactions.ts` (seven today), and a retired id keeps its total, counted by `reactionTotals` and never shown as a chip. Same loader (`reactionsLoader`), same directory rules (`scripts/check-reactions.mjs`, sharing `scripts/data-files.mjs` with the comment check, in `npm run check:posts`) and same file-system probe (`getReactionThreads()` via `hasDataFiles`) as the comments.
  - `src/content/posts/*.md(x)` — articles, validated against the strict post contract (`src/content/post-schema.ts`, ADR 0004). A post is live when `draft` is not true and its `pubDate` has passed at build time (`src/lib/schedule.ts`); a future `pubDate` is a scheduled post. `getPostPages()` builds a page for every live post, withdrawn ones included (title and notice only, `noindex`); `getPublishedPosts()` feeds every list, feed, sitemap and the search index and leaves withdrawn posts out.
  - Scheduled posts go live through `.github/workflows/scheduled-publish.yml`: hourly at minute 7 it runs `scripts/due-posts.mjs` and, if a post fell due in the last two hours, dispatches the normal deploy.
  - `src/content/authors/*.md` — author profiles; a post's `author` must match one.
- **Routes** (`src/pages/`): home, `/posts/[slug]`, `/section/[section]` (the seven habitats from `src/lib/habitats.ts`; the five retired desk URLs render a noindex redirect page built by `src/lib/redirect-stub.ts`, and `public/_redirects` gives Cloudflare a real 301 for them), `/authors/[id]`, `/archive/` + `/archive/[year]/` + `/archive/[year]/[month]/` (month grouping in `src/lib/archive.ts`, UTC), `/section/` (habitat index), `/extinction-watch/`, `/campfire/`, `/about/`, `/privacy/`, `/terms/`, `/search/` (noindex; see "Search" below). Machine-readable: `/rss.xml` and `/feed.json` (newest 50), `/llms.txt`, `/contract/post.schema.json` and `/contract/comments.schema.json` (each also under `/contract/v1/`), `/comments/threads.json` (every live post's slug with its thread state, `open` or `closed`, for the comments Worker; rule in `src/lib/comment-threads.ts`: withdrawn posts and `comments: { closed: true }` are closed, drafts and scheduled posts absent), `/sitemap-index.xml` (no withdrawn or scheduled posts; lastmod per post, `scripts/sitemap-data.mjs`) and `/news-sitemap.xml` (last 48 hours).
- **Shared code:** `src/lib/site.ts` (site constants, sections, `withBase()` for the path prefix), `src/lib/covers.ts` (hero/cover selection), `src/layouts/BaseLayout.astro`, `src/components/`.
- **Styling:** `src/styles/bestiary-tokens.css` and `src/styles/global.css`: the Bestiary night theme, described in `docs/bestiary.md` (the retired Big Top theme is at tag `checkpoint/0.1.5`). Theme helpers: `src/lib/bestiary.ts`.
- **SEO:** NewsArticle, BreadcrumbList and (for embedded videos) VideoObject JSON-LD on posts, WebSite on the home page, `max-image-preview:large` on indexable pages, `noindex` on withdrawn posts, redirect pages and search.
- **Publish times:** `pubDate` holds a full UTC time for every published post, written by `scripts/stamp-post-times.mjs` (`npm run stamp`) from git history. The same command gives each published post a permanent specimen number from the append-only ledger `src/content/specimen-ledger.txt` (`scripts/stamp-specimens.mjs`; format and repair in `POST.md` section 4). `npm run check:posts` enforces both: in `deploy-pages.yml` before every deploy, and in `check-posts.yml` on every pull request and every push to another branch. The scripts read frontmatter through `scripts/frontmatter.mjs`, which parses it with `js-yaml` the way Astro does, so they never disagree with the build about what a post says. Listings sort newest first, ties broken by post id.
- **Hero images:** JPEGs in `public/heroes/`. `scripts/decode-heroes.mjs` runs before every dev/build to assemble any base64-encoded hero parts into binaries.
- **Incremental build:** `experimental.incrementalBuild` reuses HTML for unchanged pages when `node_modules/.astro` is restored from the CI cache. Build concurrency must stay at 1 or Astro disables the cache.

Only `src/pages/` and `public/` reach the published `dist/`. Repository documents (`*.md` in the root, `docs/`) are never published.

- **Search:** `pagefind@1.5.2` (exact devDependency; vetting: `docs/reports/2026-09-25-pagefind-vetting.md`) runs as `pagefind --site dist` at the end of `npm run build`, after `astro build` has written the HTML — so search exists only after a build, never in `npm run dev`. It walks `dist/` for `data-pagefind-body` (the article element on `src/pages/posts/[slug].astro`; withdrawn posts carry none, so they drop out of the index) and writes the index and a browser search bundle to `dist/pagefind/`. `src/pages/search/index.astro` mounts Pagefind's Default UI from that bundle; the habitat is exposed as both `data-pagefind-filter` and `data-pagefind-meta`, and the specimen number as `data-pagefind-meta`, on the post's kicker line.

## Publishing

| Destination | Workflow | Build settings |
|---|---|---|
| https://aitamer.news (Cloudflare Pages, project `aitamer-news`) | `.github/workflows/deploy-pages.yml` — runs `npm test` and `check:posts`, builds, runs `check:dist`, uploads `dist/` | defaults: site `https://aitamer.news`, base `/` |
| https://contact.aitamer.news/ (contact Worker `aitamer-contact`) | `.github/workflows/deploy-contact-worker.yml`, only when `workers/contact/**` changes | `workers/contact/wrangler.toml` |

Both trigger on a push to `main`. Google Analytics loads only on the main domain.

`ASTRO_SITE` and `ASTRO_BASE` (applied through `withBase()` in `src/lib/site.ts`) still work for a future base-path deployment target, but nothing sets them today. A GitHub Pages copy built with `ASTRO_BASE=/aitamer-news` until it was retired on 2026-09-25; its workflow, `.github/workflows/deploy-github-pages.yml`, is disabled but kept in the repo.

## Server code — the contact Worker

The site itself is static files only (no `functions/`, no Astro adapter). The one piece of server code is a separate Cloudflare Worker, `aitamer-contact`, on its own hostname `https://contact.aitamer.news/`, deployed from `workers/contact/`.

- `workers/contact/src/index.mjs` — entry; answers only `/`, 404 elsewhere. Exports nothing but the handler: workerd treats every named export of the entry module as an entrypoint and refuses to start on anything else.
- `workers/contact/src/handler.mjs` — the checks, cheapest first: method → origin allowlist → body size (≤ 32 KB, before reading) → rate limits (5/min per IP, IPv6 counted per /64; 30/min site-wide; fails closed without the bindings) → parse → Turnstile (when its secret is set) → send. JSON answers for `fetch`, a 303 back to the About page for a plain submit.
- `workers/contact/src/message.mjs` — field limits, cleaning (control characters stripped, one-line names, strict addresses), honeypot, and the letter (From `desk@aitamer.news`, Reply-To the visitor).
- `workers/contact/src/turnstile.mjs` — server-side Turnstile check (5 s timeout; any failure is a rejection). A token Cloudflare accepts must also have been solved for the action `contact` (`TURNSTILE_ACTION`, which the About page's widget declares as `data-action`) on the hostname `aitamer.news` (`TURNSTILE_HOSTNAME`), mirroring the comments Worker's check for `comment`, so a token from one form cannot be spent on the other.
- `workers/contact/wrangler.toml` — custom domain, `send_email` binding (sender locked to the desk address), two rate-limit bindings; `workers.dev` and preview URLs off; Cloudflare's per-request invocation logs off (they carry visitor IPs, and the privacy page says the count is not kept).
- `workers/contact/test/contact.test.mjs` — part of `npm test`.

Secrets (`CONTACT_TO`, optional `TURNSTILE_SECRET_KEY`) are Worker secrets. The site build never has them; `npm run check:dist` fails CI if a secret name or a known secret value appears in `dist/`. The form's address is `CONTACT_ENDPOINT` in `src/lib/site.ts` (override with `PUBLIC_CONTACT_ENDPOINT` for local work). Deploys: `.github/workflows/deploy-contact-worker.yml`, only when `workers/contact/**` changes. Why this design: `docs/adr/0003-contact-form-runs-on-a-worker.md`.

## The comment form and the comments Worker

**Go-live order: the contact form goes live before comments open**, because it is the removal channel: the privacy page tells a reader to ask for a comment's removal through it. The contact Worker is deployed and `CONTACT_FORM_LIVE` set first; `TURNSTILE_SITE_KEY`, which is what makes the comment form appear, comes after (`README.md`, "Contact form"). Until `CONTACT_FORM_LIVE` is true, the About page, the Campfire and the privacy page say the form opens soon and link to no form.

The comments Worker (`https://comments.aitamer.news/`) lives in the desk's private repository; this site holds only the form and the two files the Worker reads. `src/components/CommentForm.astro` renders, on each story page, a plain `<form method="post">` to `COMMENTS_ENDPOINT` (`src/lib/site.ts`; `PUBLIC_COMMENTS_ENDPOINT` overrides it for local work) that works without script — the Worker answers a plain submit with a 303 back to `/posts/<slug>/?commented=1#comment-held`, and the held note `#comment-held` is always in the page but shown by CSS only while it is the `:target`, since a static page cannot read the query without script — and a script that turns the submit into a `fetch` showing the held message in place. The script keeps the submit button off until Turnstile's `data-callback` delivers a token and again after each attempt, expiry or Turnstile error, shows a Worker's failure reason only when it is a short string (`commentErrorText`), and the endpoint must be `https:` (plain `http:` only for `localhost` and `127.0.0.1`). Fields (`src/lib/comment-form.ts`): `slug`, `name` (1–60), `text` (1–2,000), the honeypot `desk_extra`, Turnstile's `cf-turnstile-response` from a widget with `data-action="comment"` (the Worker requires that action and the aitamer.news hostname, so a token solved on the contact form cannot be spent here), and `elapsed`, whole milliseconds between render and submit measured with `performance.now()` and added by the script alone, so a no-script submit carries none. Turnstile is mandatory for comments (plan D8): without JavaScript the `<noscript>` note says so, and with no `TURNSTILE_SITE_KEY` the page says commenting is not set up yet rather than rendering a form that cannot succeed. Turnstile's `api.js` loads only where the form renders. A post with `comments: { closed: true }` (or withdrawn) shows "comments are closed" instead; `/comments/threads.json` carries the same state to the Worker.
